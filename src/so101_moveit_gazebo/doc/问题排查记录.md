# SO101 Gazebo 问题排查记录

格式：现象 / 原因 / 解决办法。环境：ROS 2 Humble + Gazebo Classic 11，工作区 `so101_moveit_gazebo/`。

---

## 1. Gazebo 中机器人"隐形"

**现象**：spawn 成功但界面看不到机器人。
**原因**：mesh 用 `package://`，Gazebo 会转成只按 `GAZEBO_MODEL_PATH` 查找的 `model://`，找不到就静默不显示；报错只写在 `~/.gazebo/server-11345/default.log`（`grep -a`），不进 ROS 日志。另一层根因是 spawn 时 gzclient 未就绪，实例视觉丢失（物理数据正常）。
**解决**：mesh 路径统一写 `file://$(find pkg)/...`（Gazebo/RViz 都认）；隐形但物理正常时 `delete_entity` 删掉重 spawn。

## 2. Spawn 失败：`Entity [so101] already exists`

**现象**：重跑 launch 报实体已存在。
**原因**：上次 gzserver 没退干净，新 spawn 连到了旧实例。
**解决**：重跑前 `pkill -x gzserver; pkill -x gzclient`（别用 `pkill -f`）。

## 3. KDL 警告：根链接带惯性

**现象**：robot_state_publisher 报 `root link base_link has an inertia`。
**原因**：KDL 不允许根链接有惯性。
**解决**：加无质量 `world` 虚链接做根，fixed 挂 base_link（只加在 gazebo 版 xacro）。

## 4. 机器人放着不动会下沉/歪斜/漂移

**现象**：整机逐渐下沉歪斜。
**原因**：position 接口在 Gazebo 里是 PID 伺服，默认增益太弱，保持力矩抵不过重力。
**解决**：加 `world` 固定关节防整机倾倒；关节级 `pos_kp/pos_ki/pos_kd` 可调增益，但本包最终走传送模式（见第 11 条），此问题由 world 固定 + 快速激活控制器解决。PID 三项含义与调参详解见 `../so101_moveit_mujoco/src/so101_moveit_mujoco/doc/control_basics.md` 第 1 节。

## 5. RViz 报 `Package [so101_moveit_gazebo] does not exist`

**现象**：RViz 取不到 mesh。
**原因**：新终端没 `source install/setup.bash`。
**解决**：运行前先 source 工作区。

## 6. `hold_joints has already been declared`

**现象**：gazebo_ros2_control 报参数重复声明。
**原因**：arm/hand 两个 ros2_control 块都声明同名参数，已知现象。
**解决**：无害，忽略。

## 7. gzclient 报 `Missing model.config`

**现象**：客户端扫描 share 目录报错。
**原因**：把普通包目录误当模型目录扫描。
**解决**：无害；mesh 改绝对路径后自动消失。

## 8. Gazebo 界面卡住/假死

**现象**：界面白屏、不刷新，但数据侧一切正常。
**原因**：WSLg 渲染慢；更常见是 gzclient 连 models.gazebosim.org 拉模型列表卡死主线程（日志里 `ModelDatabase.cc Unable to get model name` + curl SSL 报错刷屏）。
**解决**：launch 已设 `GAZEBO_MODEL_DATABASE_URI=''`；日常看模型用 RViz，Gazebo 只当后台物理引擎。

## 9. 控制器加载时机

**现象**：launch 同时起 controller 报服务不存在。
**原因**：controller_manager 由 gazebo_ros2_control 插件在 spawn 之后才启动。
**解决**：`RegisterEventHandler + OnProcessExit` 链式加载：spawn 退出 → joint_state_broadcaster → arm → gripper。

## 10. RViz 报 `Error retrieving file`（裸绝对路径 mesh）

**现象**：同一个模型 Gazebo 正常、RViz 对所有 STL 报取文件失败且错误信息为空。
**原因**：RViz 的 resource_retriever 只认 `package://` 和 `file://`，裸绝对路径没有 URL scheme，libcurl 直接报 `CURLE_URL_MALFORMAT`，不发起任何文件读取。
**解决**：mesh 路径统一加 `file://` 前缀。教训：Gazebo 能读裸路径不代表 RViz 能读。

## 11. 夹爪下垂复查：position 默认是传送模式，力矩 PID 路线不可行

**现象**：Gazebo 版启动瞬间夹爪/手腕垂一下再恢复，怀疑默认增益弱。
**原因**：Humble 的 gazebo_ros2_control 中 position 接口**不写 PID 参数就走传送模式**（`SetPosition` 直接摆位），激活后其实零下垂；下垂只在 spawn 到控制器激活的窗口期。力矩 PID 实验（kp 20~50、100~500Hz）全部剧烈振荡，轻量臂（J~1e-4）显式力矩控制稳定 kp<10，重力静差不可接受。
**解决**：维持默认传送模式，spawn 延时缩短压缩下垂窗口。力矩 PID 为什么振荡、P/I/D 各管什么详见 `../so101_moveit_mujoco/src/so101_moveit_mujoco/doc/control_basics.md` 第 1 节。教训：改增益前先读源码确认控制模式语义。

## 12. position 模式夹爪永远抓不起物体

**现象**：方块放钳口之间发闭合指令，物体被碰飞或穿透掉地，调摩擦无用。
**原因**：传送模式没有接触过程，钳口瞬间跳到目标角，不产生夹持力。
**解决**：gripper 命令接口改 effort + position，控制器换 `effort_controllers/JointGroupEffortController`，新增测试物体由 launch spawn。注意：闭合方向为**负 effort**（关节下限 -0.17=合，上限 1.74=张，符号以实物为准）；夹紧后保持非零 effort 维持夹持；effort 闭合的反作用力会让腕关节漂移，固定 spawn 坐标会失效。

## 13. 夹爪控制器激活报 `Not existing: gripper/effort`

**现象**：重跑 launch 时 gripper 控制器激活失败，报接口不存在，但 xacro 里明明有。
**原因**：只 pkill 了 gzserver/gzclient，残留的旧 launch 进程和 robot_state_publisher 还在，插件从旧服务拿到加 effort 之前的旧 URDF，硬件接口是插件启动时一次性注册的。
**解决**：`pkill -f so101_gazebo.launch.py` 再 pkill gzserver/gzclient，整体重启 launch。排查先看 `ps aux | grep robot_state_publisher` 是不是多个实例。

---

**通用提醒**

- 改完先 `colcon build` 再用 `xacro <顶层文件>` 验证（`$(find pkg)` 解析到 install 目录）。
- 行为与源码不符时，先 `rm -rf build/<pkg> install/<pkg>` 全量重建再下结论。
- mesh URI 必须带 scheme：RViz 只认 `package://`/`file://`，Gazebo 两者加裸路径都行，本包统一 `file://$(find pkg)/...`。
