# so101_moveit_gazebo 文件说明

SO101 机械臂的 ROS 2 仿真包：Gazebo Classic 物理仿真 + ros2_control 控制 + RViz 显示 + 固定外置相机。工作区根目录为 `so101_moveit_gazebo/`，ROS 包在 `src/so101_moveit_gazebo/`（与 so101_moveit_mujoco 相同布局，`colcon build` 后安装到 `install/so101_moveit_gazebo/`）。

```
src/so101_moveit_gazebo/
├── launch/                          # 启动文件
│   ├── so101_display.launch.py      # 纯显示+mock 硬件（无 Gazebo）
│   └── so101_gazebo.launch.py       # Gazebo 仿真主入口
├── urdf/                            # 机器人描述（xacro）
│   ├── so101.urdf.xacro             # mock 版顶层（display 用）
│   ├── so101_gazebo.urdf.xacro      # Gazebo 版顶层（gazebo 用，含 world 固定+插件）
│   ├── so101_description.xacro      # 机械臂本体描述（link/joint/mesh，两版共用）
│   ├── so101.ros2_control.xacro     # 手臂 5 关节的 ros2_control 硬件块
│   ├── so101_hand.ros2_control.xacro# 夹爪的 ros2_control 硬件块
│   ├── so101_new_calib.urdf         # 旧标定结果导出的静态 URDF（当前未被引用）
│   ├── camera/
│   │   └── so101_camera.xacro       # 固定外置 RGB 相机（link+光轴系+Gazebo 插件）
│   └── assets/                      # STL 网格模型（视觉+碰撞共用）
├── objects/
│   └── cube.urdf                    # 测试方块（2cm 立方体，夹取验证用）
├── config/
│   ├── so101_ros2_control.yaml      # controller_manager 及三个控制器的参数
│   └── so101_display.rviz           # display launch 的 RViz 布局
├── CMakeLists.txt / package.xml     # 构建与依赖
└── doc/                             # 文档（本文件、问题排查记录.md、记录.md）
```

## launch/

### so101_display.launch.py — 无仿真快速显示
- xacro 展开 `so101.urdf.xacro`(mock 硬件），`robot_state_publisher` 发布 TF;
- `ros2_control_node` 加载 **mock_components** 假硬件，控制器通过 remap 订阅 `/robot_description` topic 拿模型；
- 启动 `joint_state_broadcaster` + `arm_controller`(JTC)+ `gripper_controller`（位置）;
- 开 RViz。启动快、不吃渲染资源，日常调姿态/验证模型用它。

### so101_gazebo.launch.py — Gazebo 仿真主入口
- xacro 展开 `so101_gazebo.urdf.xacro`(gazebo 硬件 + world 固定）;
- 拉起 Gazebo Classic 空世界，`spawn_entity` 生成机器人（`TimerAction` 延 2s 再 spawn，缩短"机器人在世界里但控制器未激活"的下垂窗口）;
- 机器人就位后再延 4s spawn 测试方块 `objects/cube.urdf`（落在夹爪钳口之间）;
- controller_manager 由 **gazebo_ros2_control 插件**在 spawn 后内部启动，spawn 退出 → 链式 `ros2 control load_controller` 依次激活三个控制器；
- `image_view_node` 显示相机画面（需 `sudo apt install ros-humble-image-view`)。

## urdf/

### so101_description.xacro — 机械臂本体（核心）
所有 link/joint/惯量/mesh 定义，手臂 5 关节（shoulder_pan/lift、elbow_flex、wrist_flex/roll)+ 单活动指夹爪。mesh 路径统一写 `file://$(find so101_moveit_gazebo)/urdf/assets/xxx.stl`(RViz 只认带 scheme 的 URI，见问题排查记录第 10 条）。被两个顶层 xacro 共用，**改结构只动这里**。

### so101.urdf.xacro — mock 版顶层
display launch 加载。include 本体 + 手臂/夹爪 ros2_control 硬件块（`ros2_control_hardware_type=mock`)，不挂任何 Gazebo 插件。

### so101_gazebo.urdf.xacro — Gazebo 版顶层
gazebo launch 加载。除本体和硬件块（`type=gazebo`）外：
- `world` 虚链接 + fixed 关节把整机焊死（防倾倒、消除 KDL 根链接惯性警告）;
- `gazebo_ros2_control` 插件块（指定控制器参数 yaml);
- `<xacro:so101_camera/>` 挂载固定外置相机。

### so101.ros2_control.xacro / so101_hand.ros2_control.xacro
`<ros2_control>` 硬件声明：joint 列表 + command/state 接口。手臂和夹爪分两个文件、两个硬件块（对应真机两个舵机总线）。`ros2_control_hardware_type` 决定生成 mock 还是 gazebo 硬件。
**注意两臂接口不同**：手臂 5 关节只用 position 命令接口（Gazebo 传送模式，零下垂、但夹持无接触力）；夹爪 gripper 同时声明 effort + position 命令接口，配置里挂 effort 控制器——position 传送模式抓不起方块（会直接穿透/碰掉，详见问题排查记录第 12 条），必须走 effort 才能产生真实的钳口夹持力。

### camera/so101_camera.xacro — 固定外置 RGB 相机
eye-to-hand 方案：`so101_camera_link` 经 fixed 关节挂到 world（默认 `xyz="0 -0.35 0.3"` 前上方俯视，可调）,`so101_camera_optical_frame` 是光学惯例系（z 前 x 右 y 下）。Gazebo 相机插件发布 `/so101_camera/image_raw`(640x480@10Hz)+ `/so101_camera/camera_info`，图像 header 帧 ID 用光轴系（TF 由 robot_state_publisher 发）。
注意：ROS2 插件参数名是下划线风格（`frame_name`/`image_topic_name`),ROS1 驼峰写法会被静默忽略。

### so101_new_calib.urdf
旧的手动标定结果导出的静态 URDF,mesh 用相对路径 `assets/...`。历史遗留，当前没有任何 launch 引用；要启用需先把 mesh 路径改成 `file://` 绝对路径。

## config/

### so101_ros2_control.yaml
- `controller_manager`:update_rate 100Hz，声明三个控制器及类型；
- `so101_arm_controller`:JointTrajectoryController,5 关节，command/state 接口 position;
- `so101_gripper_controller`:JointGroupEffortController，单关节 gripper，单位 N·m，正值闭合、负值张开。

## objects/

### cube.urdf — 测试方块
2cm 立方体、20g、摩擦 mu1/mu2=1.0，纯几何无 mesh。由 launch 在夹爪钳口之间 spawn，配合 effort 夹爪做抓取验证。

## 夹取验证流程

```bash
ros2 launch so101_moveit_gazebo so101_gazebo.launch.py   # 方块自动 spawn 在钳口间

# 闭合夹爪（effort，单位 N·m；实测 0.1 即可稳定夹住 20g 方块）
ros2 topic pub --once /so101_gripper_controller/commands std_msgs/msg/Float64MultiArray "{data: [0.1]}"
# 张开
ros2 topic pub --once /so101_gripper_controller/commands std_msgs/msg/Float64MultiArray "{data: [-0.1]}"

# 方块/夹爪位姿（world 插件发布）
ros2 topic echo /model_states --once
```

实测：闭合后抬手臂（wrist_flex -0.48→-0.85），方块 z 从 0.167 跟随升到 0.228，验证夹持有效。
注意：position 模式（旧方案）下方块会被碰掉或穿透，永远抓不起来——这是 Gazebo 传送模式不产生接触力的必然结果，不是摩擦参数问题，详见问题排查记录第 12 条。

## scripts/

- `show_fps.py`：订阅相机图像，窗口标题栏显示实时 FPS(`ros2 run so101_moveit_gazebo show_fps.py [话题]`);
- `record_so101.sh`：数据采集(`ros2 run so101_moveit_gazebo record_so101.sh [前缀]`),ros2 bag 录制图像/joint_states/TF/控制指令,mcap 优先、缺插件自动回退 sqlite3,支持 BAG_DIR/STORAGE/DURATION/TOPICS 环境变量覆盖。

## 常用命令

```bash
cd ~/ros_study/so101_moveit_gazebo
colcon build && source install/setup.bash

# 无仿真显示（快）
ros2 launch so101_moveit_gazebo so101_display.launch.py
# Gazebo 仿真（重跑前先 pkill -x gzserver; pkill -x gzclient）
ros2 launch so101_moveit_gazebo so101_gazebo.launch.py

# 相机
ros2 topic echo /so101_camera/camera_info   # 内参
ros2 run image_view image_view_node image:=/so101_camera/image_raw   # 手动看画面
```
